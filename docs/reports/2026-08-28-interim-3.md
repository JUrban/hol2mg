## Automatic native definitions (new)

The scaling problem of report 2 is addressed: constants introduced by `new_definition`,
constants introduced by `new_specification` (kernel form `(@f. forall code. spec (f code)) code`)
and types introduced by `new_type_definition` are now translated automatically, in dependency
order (a fixpoint over the kernel definition lists), and emitted into `_definitions.mg` ahead of
the theorem shards:

- `Definition fld : set -> (set -> set -> prop) -> set := fun A R => {x :e A | exists y :e A, R x y \/ R y x}`
- `Definition TC : set -> (set -> set -> prop) -> set -> set -> prop := fun A R a0 a1 => forall TC':set -> set -> prop, (forall a00 a10 :e A, R a00 a10 \/ (exists y :e A, TC' a00 y /\ TC' y a10) -> TC' a00 a10) -> TC' a0 a1`
- `Definition matroid : set -> set := fun A => {m :e Power A :*: Power A :^: Power A | ...axioms...}` (a `new_type_definition` as a separation; `mk_matroid`/`dest_matroid` are identities)
- `Definition linear : set -> set -> (set -> set) -> prop := fun M N f => (forall x y :e R :^: idx M, f (vector_add M x y) = vector_add N (f x) (f y)) /\ forall c :e R, forall x :e R :^: idx M, f (vector_mul M c x) = vector_mul N c (f x)`
- `Definition infnorm : set -> set := fun N => choose_in (R :^: (R :^: idx N)) (fun c => forall x :e R :^: idx N, c x = sup {abs_SNo (x i) | i :e omega, 1 <= i /\ i <= dimindex N})` (specification constant: a chosen witness of its specification)

Rules: type-variable carriers become leading `set` parameters; argument roles follow the HOL
types (`A->bool` is a subset, other function types are meta functions/predicates); the arity
follows the leading lambdas of the right-hand side; hand mappings always take precedence; built-in
logical constants are never auto-defined; symbolic constant names use a registry name map
(`%` -> `vector_mul`, `**` -> `matrix_mul`).  Auto definitions are exact by construction and are
flagged `auto` in the registry / `auto:` notes in the manifest for review.  Theorems using them:
1461 in mv_vectors.
