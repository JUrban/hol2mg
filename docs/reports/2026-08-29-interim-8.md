## What was done since report 7

1. **Lambdas as data.**  A lambda in a set position is related to the elaborator's lambda by
   `lam_ext_in` (pointwise relation of the bodies); comprehensions `{x | P x}` through
   `hl_rep_chip_sep`; applied lambdas are beta-reduced on both sides; a formula in a set position
   (`if p then 1 else 0`) through `if_prop_cong`.  Lambdas of arity 2 in meta positions
   (`lam2_beta`), partial applications missing two arguments (double eta-expansion,
   `pw_eta_pred2`/`pw_eta_fun2`), and over-applied constants with meta-valued results
   (`RESTRICTION s f x`: the pointwise relation of `RESTRICTION s f` applied to `x`).
2. **Function equalities with a lambda side** (`(==>) = \p q. …`, `COND_ABS`, …): the literal
   equality of set functions is converted to the pointwise form (`eq_Pi_pointwise`), the applied
   lambdas are beta-reduced under the binder (`pw_app_conv`, `pw_app_conv_bool`), and the
   pointwise statement is bridged.  A partially applied *logical* constant on one side
   (`hl_imp p`) is related to the literal proposition of its application by
   `hl_imp_eq1`/`hl_and_eq1`/`hl_or_eq1`/`hl_not_eq1`, proved from the HOL definitions of the
   connectives (the literal data constants unfold to `p /\ q <=> p`, `!r. (p ==> r) ==> …`, …).
   The Boolean definitions `T_DEF`, `AND_DEF`, `IMP_DEF`, `OR_DEF`, `NOT_DEF`, `F_DEF` are now
   certified.
3. **Boolean conditionals as formulas** (`if p then a else b : bool`): literal
   `(p /\ a) \/ (~p /\ b)` versus native `(p -> a) /\ (~p -> b)` (`cond_bool_fwd/bwd`).
4. **Compatibility theorems** (222 → 243): `polynomial_function` (segment sums
   `sum (0..m)` as native `finsum (ordsucc m)`; `finsum` congruence), `int_mod`, `ARB`,
   `EXTENSIONAL`, `RESTRICTION`, the logical data lemmas above.
5. **Meta-valued compatibility statements.**  Registry entries whose result role is a
   meta-function or meta-predicate now get a pointwise compatibility statement
   `forall x :e D, hl_c … x = template x` (relation kinds `KPW`/`KPWP`), with the right-hand-side
   rewrites applied under the binder.

## Defects found by certification (cumulative, see DESIGN §21.7)

- **`ARB` template was unfaithful.**  HOL Light's `ARB = @x. F`; the registry template read
  `choose_in ?A (fun x => True)`, which is a *different* set in general (`choose_in` falls back to
  an arbitrary element only when no witness exists).  The public statement of `ARB` itself was
  `choose_in A (fun x => True) = choose_in A (fun x => False)` (unprovable) on
  `dev/statements-v1`.  The templates of `ARB`, `RESTRICTION`, `EXTENSIONAL` and
  `cartesian_product` now use `choose_in ?A (fun y:set => False)`; 45 public Core statements
  changed, all of them previously uncertified.
- **Carrier arguments for type-specialised registry entries.**  The generator applied the
  compatibility lemma of a type-specialised entry (`==` at `int`) with the carrier arguments of
  the polymorphic literal constant; Megalodon rejected the proof term.  Carrier arguments are
  now derived from the entry's own scheme.
- The dependency order of the bridge library was violated once (`pw_eta_pred2` used `lam2_beta`
  from a later file) and caught by the base check.
