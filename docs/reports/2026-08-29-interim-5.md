## What was done

1. **Validation gaps (B1–B5)**: fatal source-IR gate (`source_type_error`, exit 3, negative
   test), 251 reviewed golden fixtures in 16 categories (`tests/golden/core.*`, `tools/golden.py`),
   CI workflow + `tools/lint.sh` + `tools/doc_counts.py` + `tools/check_native.sh`, all five
   admitted prelude theorems proved (native modules: 73 `Qed`, 0 `Admitted`), README/DESIGN counts
   corrected and checked mechanically.
2. **Literal layer** (`lib/literal.ml`, `mglib/literal/model.mg`): syntax-directed `L`/`LP`
   interpretation of typed HOL terms, kernel definitions (216 literal definitions for Core,
   incl. choice-based recursive definitions and specifications) and type definitions (subtypes
   `hl_ty_T` with generic abs/rep); the primitive interface is fixed and documented (§21.4).
   Core: 2697 literal statements (`hlt_N`, admitted source facts) in `generated/literal/core`,
   all Megalodon-checked (`tools/check_literal.sh`, ~25 s).
3. **Bridges** (`lib/bridge.ml`): a proof-producing elaborator that reproduces the native
   statement in lockstep with `lib/elab.ml` and emits a Megalodon proof term of
   `literal -> native` using the representation lemmas of `mglib/literal/bridge.mg`
   (subset/predicate/function/Boolean representations, quantifier-domain changes for meta
   views of arity 1 and 2, iff/implication congruences, numeral evaluation, Leibniz rewriting).
   Certification modules `generated/cert/core/<shard>.mg` contain `hlt_N` (Admitted),
   `N_bridge` (Qed) and the derived public `N`; `tools/check_cert.sh` checks them and
   `tools/cert_finalize.py` sets `cert_status = native_certified` only for theorems whose shard
   checked and whose certified statement is byte-identical to the public one.
4. **Compatibility theorems** (`mglib/literal/compat.mg`, `carriers.mg`): 98 hand-proved
   theorems, from the literal definitions only (Megalodon refuses `Qed` for anything depending
   on an admitted fact, so no HOL theorem is used): reals (primitive interface + derived
   operations), integers as a translated type definition (`hl_ty_int = int`), naturals
   (numerals, `SUC`, `+`, `*`, `EXP`, `PRE`, `-`, `<`, `<=`, `MAX`, `MIN`, `EVEN`, `ODD`, `FACT`,
   `real_pow`) via generated specification lemmas (`hl_c_spec`, from `hl_recdef`), sets (`IN`,
   `SUBSET`, `EMPTY`, `UNIV`, `INSERT`), `ONE_ONE`/`ONTO`, `COND`.  Generated per constant:
   unfolding lemmas, typing lemmas (literal and native carrier forms) and specification lemmas.

## Lessons (recorded in memory and CLAUDE.md)

Megalodon's `rewrite` compares subterms up to unfolding and hangs on `mul_SNo`-containing
goals; arithmetic compatibility proofs are written as proof terms (`eq_trans_i`, `f_equal`).
`apply` does not beta-reduce lambda-headed conclusions.  Leibniz contexts must use binder
names that cannot clash with HOL variables (`hl__u`).
