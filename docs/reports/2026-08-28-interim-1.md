## Decisions and deviations from the design document

1. **Native layer first, literal layer deferred.** The user's priority is correct native
   statements; the GRUNGE-style literal translator (`lib/literal.ml`) is a stub. The design's
   Milestone 2 is reordered after Milestone 3/4.
2. **Build:** plain `Makefile` + `ocamlfind` (yojson, str, unix); dune is not installed.
3. **Registry format:** JSON (`mappings/core.json`), templates written in Megalodon syntax with
   `?1..?n` argument placeholders and `?A` type-carrier placeholders, parsed by a small
   precedence parser that shares the notation table with the printer. Roles:
   `set | prop | subset | metafun[/k] | metapred[/k]`.
4. **View discipline** (design §5) implemented by usage analysis: a function/predicate variable
   is meta (`set -> set`, `set -> prop`) unless some occurrence is a data occurrence (bare in a
   `set`/`subset` slot, stored, compared as a member of a carrier); then it is a set-function
   `f :e B :^: A` or a subset `s c= A`. Function equality is emitted pointwise unless both sides
   are data. Meta functions get bounded closure premises `forall x :e A, f x :e B`.
5. **Nonemptiness:** `A <> Empty` is emitted per type variable, then a syntactic empty-carrier
   evaluator (`lib/emptycase.ml`) tries `A := Empty`; if the statement reduces to `True` the
   premise is dropped and the theorem is tagged `generalization_required` with bridge
   `empty_case:A` (Megalodon proof of the empty case is future work).
6. **Notation table is empirical.** Megalodon notations declared inside sections do not survive
   `End` (`:*:` is `setprod`, `:^:` is `setexp`), while some do (`+` is `add_SNo`). Instead of
   guessing, `tools/probe_notations.py` asks Megalodon which constant each symbol denotes at the
   end of the signature (definition-hash comparison) and writes `mglib/God1.notations.json`.
7. **Reuse instead of duplication.** Megalodon's `-warnaboutreproven` warnings are collected by
   the checker into `known_props.txt`; a second translation pass emits those theorems as
   comments with status `native_reuse` (67 in core, e.g. `IN_UNIV`, `SUBSET_REFL`).
8. **Choice:** `@x. P x` is `choose_in A (fun x => P x)` with
   `choose_in` defined in `mglib/native/prelude.mg` to return a member of `A` when nothing
   satisfies `P` (HOL's behaviour), rather than raw `Eps_i`.
9. **Sets:** HOL predicates in data position are subsets (`Power A`); `IN` is `:e`; set
   comprehensions (`GSPEC`/`SETSPEC` patterns) become `{x :e A | P}`, `{t | x :e A}`,
   `{t | x :e A, P}` and a family union for two bound variables.
10. **Numbers:** `num` → `omega`, `int` → `int`, `real` → `R` with the identity as the
    injections (`omega c= int c= R` in God1); arithmetic uses the SNo operations that God1's
    final notation state prints as `+ * ^ - < <= :/:`; `CARD` → `finite_cardinality`,
    `sum/nsum/product/nproduct` → prelude `finsum/finprod`, `iterate` → prelude `iterate_op`.
11. **Internal construction types** (`hreal`, `nadd`, `recspace`, `ind`) are declared
    `status: internal`; their 170 theorems are quarantined by design.

## Known gaps and next steps (in order)

1. Lists → native finite sequences (`finseq A = \/_ n :e omega, A :^: n`); 152 core theorems.
2. `cart` / `finite_image` / `dimindex` mapping decision (vectors as `A :^: n`).
3. Prove the prelude theorems (currently `Admitted`) and the empty-case rules; make the empty-case
   evaluator rule-driven from the registry so prelude constants (`seq_map _ Empty = Empty`) help.
4. Definitions: the design's §6.2 classification is not yet implemented; only theorems are emitted.
5. Side-by-side review page (design §13.5) — manifest has all inputs; HTML generation missing.
6. Second profile (`standard`: Library/analysis, etc.) to exercise repeatability across profiles.
7. Literal semantic layer (design §9.2) once native statements stabilise.

## Critical look

- The view inference is heuristic-free but coarse: a variable with one data occurrence becomes a
  set function everywhere. Readability is acceptable because applicative use prints the same,
  but closure premises then come from `:^:` membership instead of explicit `forall x :e A`.
- Definitional theorems (`o_DEF`, `FUN_EQ_THM`) become trivial identities after beta/pointwise
  elaboration; they are still emitted (correct but useless). A later pass could mark
  `trivial_after_mapping`.
- The `A <> Empty` evaluator is syntactic; it cannot use facts like "`B :^: A` is nonempty when
  `B` is", so ~300 premises remain that a reviewer might drop. Keeping them is sound.
- `finsum`/`iterate_op` are defined via God1's `finite_enumeration` (a choice-based
  enumeration); their bridge to HOL's `ITSET` is an obligation that has to be proved, not
  assumed.
